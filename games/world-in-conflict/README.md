## Where things stand

No co-op campaign mod exists yet. Working prototype (GOG test copy, 2026-10-17): with four
small exe patches, a LAN-hosted game on a campaign map runs the real campaign mission, and a second
client can join and watch the live, synchronized mission. Player 2 cannot act yet (no units or
reinforcements, no fog of war). Details, offsets and test logs are in [NOTES.md](NOTES.md).

## How the game works (for co-op)

Observed on the build above unless marked otherwise.

- **Executables and builds.** The Steam `wic.exe` and `wic_online.exe` are SteamStub-wrapped:
  `.bind` section, encrypted `.text`. Don't unpack them. The GOG Complete Edition exe is the same
  build without the wrapper: same PE timestamp and section layout, byte-identical data sections,
  and identical game archives except two localization files. Static analysis therefore uses the
  GOG `wic.exe`, plus `wic_ds.exe` (identical in both stores).
- **Play modes.** RTTI shows `EX_MultiPlayerHostMode` derives from `EX_SinglePlayerMode`: a
  multiplayer host is the single-player mode plus a network server. The host's `InitGame` calls
  the shared game setup with a single-player bool set to 0 (one `push 0` at `0xb3f386` in the
  GOG exe).
- **Archives.** `.sdf` files start with `RYS\n` and hold raw zlib streams. Scanning for zlib
  headers recovers the files; the name index is not decoded yet.
- **Mission logic is server-side Python 2.5.** Each map has `python/server.py` (mission logic,
  generated by WicEd then edited), `server_autogen.py`, `client.py` (client-side cameras and
  cutscenes), `mapvars.py` and `allunits.py`. `serverimports.py` forwards engine events
  (`OnUnitDestroyed`, `OnZoneTaken`, `OnPlayerConnected`, `OnPlayerLeave`, `OnPlayerAction`, ...)
  into a reaction system, each gated on `wicg.IsSinglePlayer()`. Scripts address the human
  player as a single constant `PLAYER_HUMAN`, which is the main script-side obstacle for two
  humans.
- **One server class, one flag.** In `wic_ds.exe` the server game object asserts
  `myIsSinglePlayerGameFlag` on one byte of `EXG_Game`. The role-selection handler checks the
  same byte: it refuses SP roles in MP matches and non-SP roles in SP matches.
- **Campaign maps are MP maps.** Running the dedicated server once per stock map-cycle name
  showed each MP name loads a map folder that is also a campaign mission. Examples:
  `do_Riviera` → `europe4` (WiC mission 6), `do_SpaceNeedle` → `seattle1` (WiC mission 14).
  Every WiC campaign map has an MP twin. Three Soviet Assault-only maps have none: `usfarmland5`,
  `berlin1` and `norway1`. Full table in [NOTES.md](NOTES.md). One map file carries both the MP
  modes and the single-player data, and 19 mission scripts have separate `OnGameStarted`
  branches for single and multi.
- **The dedicated server can't start the SP mode from config.** The map cycle takes MP names;
  folder names are ignored.
- **Single player has no real socket.** During a campaign mission `wic.exe` had no TCP sockets
  and one ephemeral UDP socket. The dedicated server listens on TCP/UDP 48000. Together with
  `MN_LoopbackConnection` in the binary, this points to server and client in one process over
  an in-memory loopback (inferred).
- **Saves.** `WICP_SaveGameHandler` and `EXCO_Persistent*` exist client-side; co-op saves are
  not studied.

## What we changed

Prototype patches to a copy of the GOG `wic.exe` (offsets for that build; full detail in NOTES.md):

| # | Where | Change | Result |
|---|---|---|---|
| v1 | `0xb3f387` | MP host `InitGame(0)` → `InitGame(1)` | host builds the campaign mission |
| v2 | `0xb3f393`–`0xb3f3d7` | pass the single-player script folder to Python init, as single player does | mission scripts load |
| v3 | `0xb3f7cc`–`0xb3f7e3` | create the host's local player with the single-player role and flags | host plays the mission |
| v4 | `0x7529d8` | `PlayerSetRole` accepts any role in a single-player match | a second client can join |

Pitfall found: the `-pythondebug` switch breaks every Python import in the retail build (even plain
single player), which masked results until it was removed.

Tooling: a call-tracing DLL plus launcher (own code) that logs arguments and results of chosen
call sites; it found the failing step in one run where log reading had not.

   Move the patches into a runtime proxy DLL keyed on byte signatures, so it works on the GOG

   `steam_api.dll` inside `wic.exe`, which is already a Steam app.

   game between them has not been tried.
5. Decode the `.sdf` name index so mission scripts can be overridden by path.
